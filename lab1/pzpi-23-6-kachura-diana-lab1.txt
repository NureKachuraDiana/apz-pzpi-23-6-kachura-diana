1.3 Короткий опис системи


Програмна система EcoMonitor призначена для автоматизованого моніторингу екологічного стану місцевості з використанням IoT-пристроїв. Система забезпечує збір, передачу, збереження, обробку та візуалізацію екологічних даних у режимі реального часу. Джерелом даних виступають сенсори, що вимірюють основні параметри довкілля, зокрема температуру повітря, рівень вологості, концентрацію шкідливих речовин (CO₂, пил), рівень освітленості та інші показники.
Отримані дані передаються на сервер через REST API, де проходять обробку, перевірку та зберігаються у базі даних для подальшого аналізу. Користувачі взаємодіють із системою через Web та мобільний застосунок, які надають можливість перегляду інформації у вигляді інтерактивних карт, графіків та статистичних показників, а також отримання сповіщень у разі перевищення допустимих норм.
Система підтримує багаторівневу модель доступу користувачів, інтеграцію з зовнішніми сервісами та забезпечує базові механізми безпеки даних. EcoMonitor може бути використана для локального або масштабованого моніторингу екологічної ситуації з можливістю подальшого розширення функціональності, зокрема із застосуванням технологій штучного інтелекту.

Окрему увагу приділено можливостям інтеграції ШІ, включаючи варіанти його застосування, підходи до збирання даних та способи навчання і використання моделей. Це дозволило сформувати більш повне уявлення про перспективи розвитку системи та потенційні ризики її реалізації.

3 SCOPE AND LIMITATIONS (РАМКИ ТА ОБМЕЖЕННЯ)
3.1   Scope of Initial Release (Рамки первинного випуску)

Початковий випуск програмної системи EcoMonitor включатиме основні функції, необхідні для збору, обробки, збереження та відображення екологічних даних з датчиків у реальному часі.
Система складатиметься з IoT-пристроїв (емуляція у Wokwi), серверної частини, Web-клієнта та мобільного застосунку, які взаємодіють між собою через REST API.
IoT-пристрої здійснюють вимірювання параметрів навколишнього середовища (температура, вологість, рівень забруднення повітря) та передають ці дані на сервер з певною періодичністю.
Серверна частина забезпечує приймання даних, їх обробку, збереження у базі даних, обчислення середніх значень, виявлення перевищення допустимих норм та формування сповіщень. Також сервер надає API для взаємодії з клієнтськими застосунками.
Web-клієнт надає користувачам та адміністраторам можливість перегляду даних у вигляді карти, графіків і таблиць, а також управління точками моніторингу.
Мобільний застосунок (Android) дозволяє користувачам переглядати актуальні показники, отримувати сповіщення про перевищення норм та працювати з картою точок моніторингу у зручному форматі.
Система забезпечує повний цикл роботи з даними: від їх збору IoT-пристроями до відображення та аналізу на клієнтських застосунках.

1. Серверна / Back-end частина:
IR–1. Реєстрація користувачів
Користувачі (адміністратори або спостерігачі) мають можливість зареєструватися в системі, вказавши email і пароль.
IR–2. Авторизація
Усі користувачі входять у систему за допомогою електронної пошти та пароля.
IR–3. Реєстрація точок моніторингу
Адміністратор може додавати нові пункти моніторингу, вказуючи їх назву, місцезнаходження (GPS-координати) та список підключених датчиків.
IR–4. Приймання даних із сенсорів
Сервер отримує дані від IoT-пристроїв через REST API (емуляція через Wokwi).
IR–5. Збереження екологічних показників
Дані з датчиків зберігаються у базі даних із зазначенням часу, координат та типу вимірювання (температура, вологість, CO₂ тощо).
IR–6. Відображення середніх значень
Система обчислює середні значення показників за день або годину для подальшої аналітики.
IR–7. Система сповіщень
Якщо рівень певного показника перевищує допустиму норму, система формує сповіщення для адміністратора.
IR–8. API для клієнтських застосунків
Надається API для отримання історії вимірювань, поточних показників і списку активних точок моніторингу.
IR–9. Шифрування даних
Передача даних між сервером та клієнтами здійснюється через HTTPS. Конфіденційні дані користувачів шифруються.
IR–10. Резервне копіювання бази даних
Передбачено автоматичне створення резервної копії бази даних раз на добу.

2. Клієнтська / Front-end частина:
IR–11. Інтерфейс адміністратора
Адміністратор може переглядати всі пункти моніторингу, додавати нові, переглядати останні отримані дані та історію вимірювань.
IR–12. Панель користувача
Користувач бачить карту з активними точками моніторингу, короткі показники в реальному часі та може переглядати графіки змін параметрів.
IR–13. Графічна візуалізація
Показники відображаються у вигляді графіків, таблиць і кольорових індикаторів стану повітря (норма / перевищення).
IR–14. Фільтри та сортування
Можливість відбору даних за типом сенсора, датою або локацією.
IR–15. Авторизація та реєстрація
Інтерфейс входу та створення акаунта користувача.
IR–16. Повідомлення про перевищення норм
На панелі користувача виводяться повідомлення про зони з погіршеним екологічним станом.
IR–17. Локалізація мови
Система підтримує українську та англійську мови.

3. Мобільний застосунок (Android)
IR–18. Реєстрація та авторизація
Користувач може створити обліковий запис і входити в систему через мобільний додаток.
IR–19. Перегляд даних сенсорів
На головному екрані користувач бачить основні показники екологічного стану поблизу своєї локації.
IR–20. Карта точок моніторингу
Вбудована карта відображає активні пункти моніторингу з можливістю перегляду їх стану.
IR–21. Сповіщення
Застосунок надсилає push-повідомлення у разі виявлення перевищення граничних показників у найближчій зоні.
IR–22. Темна тема
Можливість перемикання між світлою та темною темами інтерфейсу.

4. IoT-пристрої / Емуляція на Wokwi
IR–23. Вимірювання параметрів довкілля
Модуль на базі емулятора Wokwi передає до серверу дані з датчиків температури, вологості та рівня забруднення повітря.
IR–24. Періодична передача даних
Дані надсилаються до сервера з певним інтервалом (наприклад, кожні 10 секунд).



3.2   Scope of Subsequent Releases (Рамки наступних випусків) 

Для забезпечення подальшого розвитку та розширення функціональних можливостей програмної системи моніторингу екологічного стану місцевості, у наступних випусках планується інтеграція технологій штучного інтелекту для підвищення точності аналізу даних, автоматизації процесів та покращення взаємодії з користувачами.

SR–1. Застосування штучного інтелекту для аналізу даних
Використання моделей машинного навчання для виявлення аномалій у показниках сенсорів (різкі стрибки забруднення, некоректні дані), а також для автоматичного визначення критичних ситуацій без заздалегідь заданих порогів.
SR–2. Прогнозування екологічного стану
Застосування ШІ для прогнозування рівня забруднення повітря, температури та інших показників на основі історичних даних, сезонності та погодних умов.
SR–3. Рекомендаційна система для користувачів
Формування персоналізованих рекомендацій (наприклад, уникати певних зон, змінити маршрут, обмежити перебування на відкритому повітрі) на основі поточного та прогнозованого стану довкілля.
SR–4. Збирання даних для навчання моделей
Система накопичуватиме історичні дані з IoT-сенсорів, включаючи:
показники температури, вологості, рівня забруднення;
часові мітки та геолокацію;
інформацію про перевищення норм;
дані з відкритих API (погода, офіційні екологічні показники);
користувацькі повідомлення (скарги, фото, геолокація).
SR–5. Обробка та підготовка даних
Зібрані дані проходитимуть попередню обробку: очищення від шуму, нормалізацію, агрегацію та формування датасетів для навчання моделей машинного навчання.
SR–6. Використання готових AI-сервісів
На початкових етапах планується використання готових API сервісів штучного інтелекту (наприклад, для аналізу зображень або базового прогнозування), що дозволить швидко інтегрувати інтелектуальні функції без складної розробки моделей.
SR–7. Донавчання існуючих моделей
У подальшому можливе донавчання існуючих моделей на основі накопичених даних системи для підвищення точності прогнозів з урахуванням локальних особливостей.
SR–8. Розробка власних моделей
При накопиченні достатнього обсягу даних планується розробка власних моделей машинного навчання для прогнозування та аналізу екологічного стану.
SR–9. Інтелектуальна обробка користувацьких даних
Використання ШІ для аналізу текстових повідомлень користувачів (наприклад, визначення типу екологічної проблеми) та обробки зображень (виявлення диму, сміття тощо).
SR–10. Оптимізація роботи системи
Застосування ШІ для оптимізації роботи IoT-пристроїв (регулювання частоти передачі даних, виявлення несправностей сенсорів).

3.3   Limitations and Exclusion (Обмеження та виключення) 

Програмна система EcoMonitor має низку обмежень та виключень, які можуть вплинути на її впровадження, експлуатацію та можливості розширення.

Обмеження (Limitations):
1. Технічні обмеження:
L–1. Обов’язкова наявність підключення до Інтернету
Для коректної роботи система потребує постійного доступу до Інтернету, оскільки передача даних з IoT-пристроїв, відображення карти, синхронізація показників і робота аналітики виконуються у хмарному середовищі.
L–2. Обмежена сумісність з IoT-пристроями
Система підтримує лише базові моделі сенсорів температури, вологості, рівня CO₂ та пилу, які протестовані у середовищі Wokwi. Для використання інших моделей може знадобитися адаптація коду прошивки або API.

L–3. Затримки передачі даних
У залежності від якості мережевого з’єднання можливі затримки у передачі даних від IoT-пристроїв до сервера, що може впливати на актуальність відображеної інформації.

2. Обмеження, пов’язані з використанням ШІ:
L–4. Залежність якості моделей від даних
Точність прогнозування та виявлення аномалій напряму залежить від обсягу та якості зібраних даних. На початкових етапах можливі неточні або нестабільні результати.
L–5. Обмежений обсяг навчальних даних
На ранніх етапах система не має достатнього обсягу історичних даних для ефективного навчання власних моделей машинного навчання.
L–6. Обчислювальні ресурси
Навчання та використання моделей ШІ потребує додаткових обчислювальних ресурсів (CPU/GPU), що може впливати на продуктивність системи та вимагати додаткових витрат.

3. Фінансові та операційні обмеження:
L–7. Витрати на розгортання системи
Для розгортання серверної частини (Node.js) та фронтенду (React) необхідні хостинг-ресурси або використання безкоштовних сервісів з обмеженою продуктивністю, що може впливати на швидкість роботи системи.
L–8. Вартість використання AI-сервісів
При використанні сторонніх API штучного інтелекту можливі додаткові витрати, залежно від кількості запитів та обсягу оброблених даних.
L–9. Необхідність регулярних оновлень
Для підтримання безпеки, сумісності з новими версіями бібліотек і точності відображення даних система потребує періодичних оновлень.

L–10. Обмежена кількість користувачів
Система оптимізована для невеликої кількості підключень і сенсорів. Масштабування для великих міст або регіонів може вимагати суттєвої модернізації серверної частини.

4. Законодавчі та регуляторні обмеження:
L–11. Дотримання норм зберігання персональних даних
EcoMonitor зберігає мінімальний обсяг користувацької інформації. Система повинна відповідати вимогам законодавства щодо захисту персональних даних.
L–12. Обмеження використання даних для навчання ШІ
Використання користувацьких даних для навчання моделей може бути обмежене політиками конфіденційності та законодавством.
L–13. Використання відкритих екологічних API
У деяких регіонах доступ до державних або муніципальних джерел даних може бути обмеженим, що впливає на точність і повноту моніторингу.

5. Функціональні обмеження:
L–14. Обмежена кількість вимірюваних параметрів
На початковому етапі система підтримує лише базові екологічні показники.
L–15. Відсутність автоматичного калібрування сенсорів
